Background: an independent review pointed out that in INSTALL [for install]
the THIRD AID field is the APPLICATION INSTANCE AID slot (not the Security
Domain), and the data field must end with an Install Token length byte.
Our historical 31-byte form put the ISD AID (A000000151000000) into the
instance slot and omitted the token length.

CORRECTION (per review): the working form below is the STANDARD GP 2.2.1
encoding - Table 11-43 encodes Privileges as an LV field (Length of
Privileges + Privileges), so '01 00' is canonical, not a card-specific
dialect. The "raw privileges byte" variants tried earlier were the
non-canonical ones (misidentified at first as 'canonical 2.2.1').

The form that installs: <L><pkg AID> <L><module AID> <L><instance AID>
<LV privileges (01 00)> <LV install params (02 C9 00)> <token len (00)>.
Putting the ISD AID into the instance slot is refused with 6985 - an honest
AID-conflict answer, not a firmware lock.
